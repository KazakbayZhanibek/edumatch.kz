# Проверка файла `bilim_beru_dengeileri_boiynsha1-v8.json`

Дата проверки: 2026-08-22

## Что внутри

Файл успешно читается как JSON-массив:

- 100 записей;
- все записи относятся к `2026 год`;
- 100 уникальных внешних ID;
- 21 регион/область Казахстана;
- поля: `nameoftheregion`, `nameoftheorganization`, `legaladdress`, `reportingperiod`, `contactphonenumber`, `id`.

Фактический смысл полей:

- `nameoftheorganization` — регион или город;
- `legaladdress` — полное юридическое название организации образования;
- `reportingperiod` — почтовый адрес;
- `contactphonenumber` — контактный телефон;
- `nameoftheregion` — год отчётности.

Это хороший источник для списка организаций высшего образования и контактов приёмных комиссий. Это **не** источник цен, грантов, проходных баллов или программ обучения.

## Важное ограничение импорта

В файле 64 внешних ID совпадают с числовыми ID в нашей БД, но сами организации по этим ID не совпадают. Например:

- внешний ID `103` — Astana IT University;
- ID `103` в текущей БД относится к другой записи.

Поэтому импортировать телефоны или названия по ID нельзя: можно записать контакт одного вуза в карточку другого.

## Как использовать безопасно

1. Сопоставлять записи по очищенному полному названию, региону и адресу.
2. Для сокращений использовать ручную таблицу соответствий.
3. Совпадения с уверенностью ниже 100% отправлять на ручную проверку.
4. Телефон сохранять в `universities.admission_phone` только после подтверждения пары.
5. Адрес сначала добавить в отдельное поле/миграцию, а не записывать в телефон или описание.
6. Для каждой записи сохранять источник файла, год `2026` и дату импорта.

## Что не следует делать

- не заменять текущие названия только по внешнему ID;
- не считать этот файл источником грантов или проходных баллов;
- не добавлять одинаковые координаты и цены по умолчанию;
- не активировать вуз без проверки официального сайта.
