# Мобильная версия — заключительная проверка 27.09.2026

> Уточнение повторной диагностики: этот документ описывает прошлый проход. Утверждение ниже о сочетании border/shadow/outline не доказывает причину линий вне фокуса: исходный угловой дефект не воспроизведён. Актуальные подтверждённые ошибки, исправления и ограничения записаны в [MOBILE_DEFECTS_CHECK.md](MOBILE_DEFECTS_CHECK.md).

## Область работы

Уплотнение и исправление мобильного интерфейса EduMatch KZ. Основные правки ограничены CSS до 768 px; десктоп не перепроектировался. Использован подход Impeccable adapt: сокращение вложенных рамок и отступов вместо уменьшения читаемости полей и зон нажатия.

Изменения этого прохода: `frontend/css/site-ux.css`, одна отсутствующая строка перевода `auth_prompt_desc` в `frontend/js/translations.js`, проверочные сценарии и этот отчёт. Другие изменения в рабочем каталоге существовали ранее. Код сервера и данные в этом проходе не редактировались.

## Исправления

- Двойная рамка поля была сочетанием border, 4 px box-shadow и общего focus-visible outline. На мобильном оставлен один контур с внутренним смещением, без тени; клавиатурный фокус сохранён. Отдельно проверен DPR 3, как на пользовательском скриншоте.
- У формы входа/регистрации убрана внешняя вложенная рамка, уменьшены отступы, исправлен размер чекбокса согласия и область переключения видимости пароля. Подвал скрыт только на этих мобильных экранах.
- Главная, карточки вузов, подробности, план поступления, профориентация, советы и гранты стали компактнее. Заголовки и вторичные блоки меньше, поля сохраняют 16 px текст, основные кнопки — не менее 44 px высоты.
- «Назад» остаётся выровненной с содержимым; лишняя рамка убрана. Программный фокус заголовка не выглядит случайным подчёркиванием на телефоне.
- Убраны зависающие после касания hover-тени и смещения кнопок/карточек.
- Исправлен конфликт отступа поля поиска со значком.
- В «Гранты → Для меня» длинный пункт select растягивал grid-колонку шире телефона. Установлены `minmax(0,1fr)`, нулевая минимальная ширина подписей и ограничение ширины полей.
- В гостевом профиле вместо технического ключа перевода отображается нормальное пояснение на RU/KK/EN.

Горизонтальное переполнение документа не найдено.
2. `artifacts/mobile-release/states.cjs`: PASS на 320 и 402 px. Ошибки входа, тестовый авторизованный профиль, отмена диалога, результат расчёта, вкладки, окно фильтров и длинный ответ чата. API полностью замоканы. Геометрия десктопной главной на 1280 px точно совпала с baseline до мобильных изменений.
3. `artifacts/mobile-release/focus-confirm-b.cjs`: login/register/planner при 402×874 и DPR 3, светлая и тёмная темы. Один контур 2 px, без box-shadow, radius 10 px, текст 16 px. Исходные угловые артефакты не воспроизводятся в этих проверках.
4. `artifacts/mobile-release/mobile-release.cjs`: заключительный PASS на 360 и 402 px. 14 маршрутов, касания карточек/меню/фильтров, ошибки входа и регистрации, фокус, длинные формы, выбор и сравнение программ, прокрутка таблиц через эмулируемый touch-жест, отправка тестовой анкеты грантов, советы и чат с уменьшенной высотой viewport. API замоканы; JS-ошибок нет.
5. Заключительный визуальный пакет просмотрен: `final-home-390.png`, `final-for-me-360.png`, `final-login-focus-402.png`. Поиск имеет отступ 40 px; у формы на 360 px ширина и scrollWidth равны 328 px; поле входа имеет один контур и высоту 44.39 px. Замеры — `artifacts/mobile-release/final-layout.json`.
6. Синтаксис `translations.js` и `git diff --check`: без ошибок; Git выдаёт только предупреждения о преобразовании LF/CRLF в существующих файлах.

Результаты и кадры: `artifacts/mobile-release/`, `artifacts/responsive-after/`. Проверки с изменяющими API-запросами изолированы: реальные аккаунты, заявки, сохранения, удаление истории и платные вызовы ИИ не выполнялись.

## Что эти проверки не подтверждают

- Это Edge/Chromium с эмуляцией касания и размеров, не физический iPhone/Safari или Android. Уменьшение viewport проверяет доступность элементов, но не полностью воспроизводит настоящую экранную клавиатуру.
- Окно сохранённых паролей на исходном скриншоте принадлежит браузеру, не сайту. Реальное автозаполнение и расширения менеджеров паролей не тестировались с пользовательскими учётными данными.
- Полный backend npm test, реальные защищённые операции, админка и загрузка документов не входили в этот мобильный проход.
- Актуальность университетских данных, полная локализация и доступность внешних CDN не подтверждаются UI-проверкой. Остальные открытые вопросы сохранены в `SITE_RESPONSIVE_AUDIT.md`.

Перед сдачей нужен короткий проход на физическом телефоне: вход без отправки, показ/скрытие пароля, поиск, фильтры, сравнение свайпом, анкета и чат с открытой клавиатурой. Нельзя честно гарантировать отсутствие всех будущих ошибок по одной эмуляции.
