# EduMatch KZ — Подробное описание сайта

## Обзор

**EduMatch KZ** — образовательная платформа для абитуриентов Казахстана. Помогает выбрать вуз, сравнить их, рассчитать шансы поступления, найти гранты и получить ИИ-консультацию.

- **URL**: http://localhost:3000
- **Языки**: Русский, Казахский, Английский
- **Темы**: Светлая / Тёмная
- **Устройства**: Десктоп, планшет, мобильные

## Страницы и функции

### 1. Главная — Вузы

**Что делает**: Показывает список всех вузов Казахстана с фильтрацией и поиском.

**Как реализовано**:
- При загрузке вызывается `loadUniversities()` — fetch GET `/api/universities?lang=...`
- Бэкенд (`db.js:getUniversities()`) выполняет SQL-запрос с динамическими WHERE-условиями
- Фильтры: город, специальность, язык обучения, макс. стоимость, сортировка
- Поиск работает на клиенте — фильтрует по `name` и `short_name`
- Рендер: `renderUniversities()` создаёт карточки с ценой, рейтингом QS, городом
- ТОП-20 вузов загружается через `?is_top=top` — SQL сортирует по QS рейтингу
- Описания вузов приходят на нужном языке (?lang=ru|kk|en) из колонок `description`, `description_kk`, `description_en`

**UI**: Карточки в виде сетки, адаптивная (3→2→1 колонка). Анимации при скролле (AOS).

---

### 2. Сравнение вузов

**Что делает**: Позволяет выбрать 2-3 вуза и сравнить их по параметрам.

**Как реализовано**:
- На каждой карточке вуза есть кнопка «+ Сравнить»
- Выбранные ID сохраняются в `state.compareList` (макс. 3)
- При нажатии «Сравнить» вызывается `loadCompare()` — fetch GET `/api/compare?ids=1,2,3&lang=...`
- Бэкенд: `db.js:getUniversity(id, lang)` вызывается для каждого ID
- `renderCompareTable()` создаёт таблицу с поперечным сравнением:
  - Цена, QS рейтинг, основные специальности, языки, общежитие, средняя зарплата
  - Цветовое кодирование: зелёный — лучше, красный — хуже
- Стоимость форматируется через `fmtPrice()` — «млн ₸» / «тыс ₸»

---

### 3. ИИ-советник (Чат)

**Что делает**: ИИ-ассистент, отвечает на вопросы о вузах, грантах, поступлении.

**Как реализовано**:
1. Пользователь вводит сообщение
2. `classifyIntent()` определяет намерение через regex:
   - `admission` — «шансы», «поступить», «ЕНТ», цифры баллов
   - `grant` — «грант», «стипендия», «бесплатно»
   - `comparison` — «сравни», «лучше»
   - `recommendation` — «посоветуй», «какой»
   - `general` — всё остальное
3. В зависимости от намерения:
   - **admission**: извлекает ЕНТ из текста, ищет вузы в `admission_requirements`, строит обзор шансов
   - **grant**: вытаскивает гранты из БД, передаёт в промпт
   - **general**: `retrieveRelevantUniversities()` ищет по ключевым словам в БД
4. Формируется системный промпт с случайной «личностью» (professional/friendly/concise/detailed)
5. Вызывается OpenRouter API (Gemini 2.5 Flash Lite)
6. Ответ рендерится как Markdown через `marked` + `DOMPurify`
7. Под чатом — карточки найденных вузов

**Дополнительно**: При admission-намерении показывает карточки вузов с процентом шансов (🟢/🟡).

---

### 4. Прогноз поступления

**Что делает**: Детерминированный расчёт шансов поступления на основе ЕНТ, специальности, города.

**Как реализовано**:
1. Пользователь заполняет форму: ЕНТ балл, специальность, город, бюджет, язык, общежитие
2. Отправляется POST `/api/admission/calculate` с `useAiExplanation: true`
3. **Детерминированный слой** (`admission-calculator.js`):
   - Запрос к `admission_chance_stats` — исторические данные по поступлению
   - Матчинг по специальности, университету, городу, языку
   - Расчёт `chance_percent` на основе `applicants_count`, `admitted_count`, `grant_winners_count`
   - Возвращает массив match'ей с процентами
4. **ИИ-объяснение** (`admission-explanation-service.js`):
   - Результаты детерминированного расчёта отправляются в OpenRouter
   - ИИ генерирует JSON: summary, strengths, risks, strategy, tips
   - **Fallback**: если ИИ недоступен — шаблонные объяснения
5. `renderAdmissionResults()` показывает:
   - Карточки вузов с процентом шансов
   - Цветовое кодирование: 🟢 ≥70%, 🟡 40-70%, 🔴 <40%
   - Объяснение: сильные стороны, риски, советы
6. Результат сохраняется в `prediction_history` (для авторизованных)

---

### 5. Профориентация (Тест)

**Что делает**: Определяет подходящие специальности и вузы на основе ответов.

**Как реализовано**:
1. 8 вопросов с вариантами ответов
2. Каждый ответ имеет веса по категориям: IT, Медицина, Бизнес, Инженерия, Образование
3. При ответе суммируются баллы по категориям
4. Результат: топ-3 специальности + подходящие вузы
5. `renderCareerResults()` показывает:
   - Гистограмму по категориям
   - Карточки вузов с релевантными специальностями
   - Подробный профиль выбранной специальности (зарплата, рост, востребованность)

---

### 6. Гранты и стипендии

**Что делает**: Каталог всех грантов с фильтрацией по типу.

**Как реализовано**:
1. `loadGrants()` — fetch GET `/api/grants?lang=...`
2. Бэкенд (`db.js:getGrants({lang})`) возвращает гранты с переведёнными name, description, requirements
3. Типы грантов: `government` (государственные), `regional` (региональные), `corporate` (корпоративные), `university` (университетские)
4. Фильтрация по типу через кнопки
5. Карточка гранта показывает: тип, сумму, название, описание, требования (JSON-массив), дедлайн, ссылку

**Данные**: 351 грант, переведённые на KK/EN (name, description, requirements).

---

### 7. Карта

**Что делает**: Интерактивная карта Казахстана с маркерами вузов.

**Как реализовано**:
- Leaflet + OpenStreetMap тайлы
- Координаты (`lat`, `lng`) хранятся в таблице `universities`
- Кластеризация маркеров (в одном городе несколько вузов)
- При клике на маркер — popup с названием, ценой, кнопкой «Подробнее»
- Цвет маркера зависит от наличия бюджетных мест
- Фильтрация по городу через dropdown

---

### 8. Советы

**Что делает**: Полезные статьи и советы для абитуриентов.

**Как реализовано**:
- Данные из таблицы `tips` (id, title, category, content, tip)
- Категории: поступление, документы, общежитие, стипендии
- Рендер в виде карточек с раскрывающимся содержимым

---

### 9. Авторизация

**Что делает**: Регистрация, вход, профиль, избранное.

**Как реализовано**:

#### Регистрация
1. Email + пароль + username
2. `auth-service.register()`: валидация уникальности, bcrypt хэширование (10 раундов)
3. Создание записи в `users`, создание JWT (7 дней), запись сессии в `user_sessions`

#### Вход
1. Email + пароль
2. bcrypt.compare() → новый JWT → запись сессии

#### Токен
- Хранится в `localStorage`
- Отправляется как `Authorization: Bearer <token>`
- `verifyAuthOptional` middleware: проверяет токен, но не блокирует если невалидный
- При ошибке сети токен сохраняется (не удаляется)

#### Избранное
- **Без авторизации**: хранится в `localStorage` как JSON массив ID
- **С авторизацией**: синхронизация с таблицей `saved_universities`
- При входе: localStorage → сервер (мердж)
- При выходе: сервер → localStorage

## Система переводов (i18n)

### Фронтенд (`translations.js`)
- **~2200 строк**, 3 языка: ru, kk, en
- Секции: навигация, главная, фильтры, сравнение, чат, поступление, карьера, гранты, карта, советы, авторизация
- Механизм:
  - HTML: атрибуты `data-i18n="key"` → `setLanguage()` заменяет `textContent`
  - JS: глобальная функция `t(key)` возвращает строку для `currentLanguage`
  - Плейсхолдеры: `data-i18n-placeholder`, `data-i18n-title`
- `currentLanguage` сохраняется в `localStorage`, применяется при загрузке

### Бэкенд (`i18n.js`)
- **~120 ключей** для KK и EN (RU — по умолчанию, обрабатывается инлайн)
- `tr(key, lang)`: возвращает перевод или null для RU
- Используется в: admission-service, ai-service, ai-prompts, admission-explanation-service

### Перевод контента из БД
| Таблица | Колонки перевода | Кол-во | Скрипт |
|---------|-----------------|--------|--------|
| universities | `description_kk`, `description_en` | 44 | `translate-descriptions.js` |
| grants | `name_kk`, `name_en`, `description_kk`, `description_en` | 351 | `translate-grants.js` |
| grants | `requirements_kk`, `requirements_en` | 351 | `translate-requirements.js` |

- Все скрипты используют OpenRouter API (gpt-3.5-turbo)
- Резумируемые: пропускают уже переведённые записи
- Батчинг: 10-15 записей за один API-запрос

## ИИ-система

### Классификация намерений
Перед вызовом LLM система определяет намерение пользователя:

```
admission    → regex: шансы, поступить, ЕНТ, балл, score
grant        → regex: грант, стипендия, бесплатно
comparison   → regex: сравни, лучше, отличие
recommendation → regex: посоветуй, какой, лучший
general      → всё остальное
```

### Личности ИИ
Случайно выбирается для каждого ответа:
- **professional** — структурированный, экспертный тон
- **friendly** — тёплый, дружелюбный
- **concise** — кратко, по делу
- **details** — развёрнуто с примерами

### Гибридный подход к расчёту шансов
1. **Детерминированный**: SQL-запрос к `admission_chance_stats` → percentages
2. **ИИ-объяснение**: OpenRouter генерирует自然ный текст на основе числовых результатов
3. **Fallback**: если ИИ недоступен — шаблонные объяснения
