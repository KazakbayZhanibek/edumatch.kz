# Исправления от 12–13 сентября 2026

## Профиль и проверка документов

- Разделены введённый вручную и подтверждённый администратором баллы ЕНТ. Допустимы целые значения от 0 до 140; изменение балла вручную снимает подтверждение.
- ЕНТ и военная служба: загрузка документа, статусы проверки, история решений, причина отказа, повторная отправка и отмена ожидающей заявки.
- Администратор может просматривать документы, фильтровать заявки, подтверждать, отклонять с обязательной причиной и уточнять балл ЕНТ.
- Документы доступны только владельцу и администратору. Проверяются размер до 5 МБ, формат и сигнатура JPEG, PNG, WEBP или PDF. Это не антивирусная проверка и не автоматическая проверка подлинности.
- Решение и запись аудита сохраняются атомарно. Повторное решение по завершённой заявке запрещено.
- После обновления статуса поле ЕНТ синхронизируется с сервером, не перезаписывая несохранённый ввод пользователя.
- Общий интерфейс проверки документов используется в профиле и админке, с переводами RU/KK/EN. Подтверждение службы само по себе не обещает льготы при поступлении.

## Безопасность админки

- Убрано автоматическое назначение администратора по адресу электронной почты. Запуск приложения больше не меняет права пользователей.
- Новая роль назначается только явной локальной командой после регистрации пользователя: `npm run admin:grant -- person@example.com`. Команду следует запускать только на доверенном сервере и только уполномоченному сотруднику.
- CSP страницы админки запрещает inline-скрипты и inline-обработчики. Тайм-аут бездействия перенесён в отдельный скрипт и выполняет серверный logout, чтобы токен отозвался и в БД.

## История расчётов и трекер

- История расчётов доступна только владельцу, включая удаление отдельных записей и очистку истории. После удаления обновляются список и пустое состояние.
- Исправлены закрытие окна очистки истории и ошибочный счётчик из другого раздела профиля.
- Статусы, даты, учебный год и заметки в трекере проходят серверную валидацию. При ошибке сохранения интерфейс возвращает фактическое состояние и показывает ошибку.
- Исторические показатели поступления разделены по вузам; исправлена сортировка уверенности прогноза.

## Администратор и каталог

- Журнал действий автоматически создаётся при обновлении существующей БД.
- Изменение вуза и запись в журнал выполняются в одной транзакции: при ошибке аудита изменение отменяется.
- Скрытые и ожидающие проверки вузы исключены из публичного каталога, карточек, сравнения и обоих калькуляторов поступления. Старые записи без статуса сохраняют прежнюю видимость.
- Кнопка «Скрыть» действительно исключает отзыв из публичного списка и среднего рейтинга. «Одобрить» возвращает его на сайт.
- Добавлены статусы отзывов «На проверке», «Одобрен», «Скрыт», фильтр в админке и журнал решений модератора.
- Новые отзывы по-прежнему публикуются сразу, со статусом «На проверке». Премодерация не включена. Старые решения «Скрыть» невозможно восстановить автоматически: раньше они не отличались от непроверенных отзывов.
- После обновления и модерации сохраняются вкладка, поиск и фильтр. Списки пользователей и заявок показывают все загруженные строки (до 100), а не только первые 20.
- Проверяется соотношение минимальной и максимальной цены обучения.

## Поступление и API

- Необязательная авторизация распознаёт httpOnly cookie, используемую интерфейсом. Это восстанавливает привязку прогнозов и AI-запросов к вошедшему пользователю.
- История принимает поля нового калькулятора, сохраняет их в правильные колонки и исключает повторы в течение 10 минут.
- Ошибки валидации калькулятора возвращают HTTP 400; неизвестные API-маршруты — JSON с HTTP 404.
- CORS разрешает PATCH для админки и трекера заявок.

## Запуск и проверка

Обновления схемы применяются при следующем запуске `npm start`. Перед обновлением рабочей базы создайте резервную копию: `npm run db:backup`.

Ошибка открытия или проверки существующей БД теперь останавливает запуск с объяснением и сохраняет исходный файл. Автоматическое удаление БД отключено.

`npm test` запускает регрессионные проверки на отдельной временной SQLite-базе с локальным HTTP-сервером. Рабочая БД и AI-провайдер в этих тестах не используются. `DB_PATH` позволяет указать отдельный файл базы; по умолчанию остаётся `backend/edumatch.db`.
