# Публикация демо — необходимые решения и проверки

Публичная версия пока НЕ размещена. Нужны выбранный хостинг/VPS и домен. Не передавать пароли или ключи в чат; задавать секреты через панель хостинга.

## Требования текущей архитектуры

- Долгоживущий Node.js-процесс, версия 22; зависимости устанавливать через `npm ci` в `backend`.
- Постоянный диск для SQLite (`DB_PATH`, абсолютный путь) и `backend/uploads`. Не использовать временную файловую систему функций для рабочей базы.
- HTTPS на обратном прокси. Прокси должен перезаписывать заголовок `X-Forwarded-Proto`, а не доверять присланному клиентом; приложение ожидает HTTPS в production.
- `NODE_ENV=production`, случайный `JWT_SECRET`, точный `ALLOWED_ORIGINS`, серверный `OPENROUTER_API_KEY`, выбранный `OPENROUTER_MODEL`. Не публиковать `.env`.
- Запуск из директории `backend`: `node server.js`. Переменная `PORT` — назначенный хостингом порт.

## Данные демо

Не копировать рабочую базу пользователей и реальные uploads в публичный стенд. Создать отдельную базу и тестовый аккаунт с отдельным случайным паролем; аккаунт без прав администратора. Локальный `preview-fixture.js` и его известный пароль предназначены только для localhost — не выставлять его в интернет.

Новый помощник использует отдельный пилотный каталог из кода. Пустая новая SQLite не содержит полноценного общего каталога сайта: перед публичной демонстрацией отдельно загрузить только проверенные публичные данные, не пользовательскую базу.

## Перед открытием доступа

- Проверить вход/выход, cookie Secure, CSRF и отсутствие доступа обычного пользователя к админским API.
- Незавершённые recovery/2FA отключены и отвечают 503. Сервис не обещает защиту вторым фактором. Восстановление почтой требует отдельной полноценной реализации.
- Установить лимит расходов у ИИ-провайдера, проверить лимиты запросов приложения и отказ при исчерпании баланса.
- Создать резервную копию SQLite штатным скриптом, проверить восстановление на отдельной копии. Хранить резервные копии вне публичной директории.
- Проверить запись и сохранность плана после перезапуска процесса и доступность официальных источников.
- Прогнать три сценария из HACKATHON_DEMO_PLAN.md по публичному HTTPS URL, включая мобильную ширину.

Эти проверки на публичном хостинге пока не выполнялись. Доступ к провайдеру и публикация — следующий внешний шаг, не результат локальных тестов.
